# このホスト（exally-test.vercel.app）で何が生きているか

作成 2026-08-04

**vercel.json にコメントは書けません**（`"//"` のような自前のキーを足すと
Vercel が設定を読む段階で弾き、**ビルドに入る前にデプロイが失敗します**。実際に1回失敗しました）。
なので説明はこの1枚に置きます。

## 塞いだもの（今の入口へ 308）

| 古いURL                                            | 飛び先                             |
| -------------------------------------------------- | ---------------------------------- |
| `/` `/index.html` `/home.html` `/exally-home.html` | https://exally.vercel.app/hub.html |

**理由**: 古いExallyホームが1枚残っていた。データは見ないので危険は低いが、
**入口が1つ増えているだけで価値がゼロ**。司さんは実際に古い入口（`payslip-app-test`）を
「テスト用だ」と誤解している。「古い」と書くだけでは人は開く。

## ★塞いでいないもの（このホストで実務が動いています）★

| URL                                                          | 何                                     |
| ------------------------------------------------------------ | -------------------------------------- |
| `/daikou-seikyu.html`                                        | **代行請求システム（実務で毎日使う）** |
| `/book.html`                                                 | Exally グリッド                        |
| `/seikyusyo.html` `/mitsumoriyo.html` `/kyuuryoumeisai.html` | テンプレート                           |
| `/api/claude` ほか `rewrites` の行                           | そのまま                               |

**塞ぐ範囲を広げる時は、必ずここを読んでから。**

## 機械の見張り

`exally` リポジトリの `node scripts/check-hosts.mjs`（週1・月曜9時JST＋手動）が、

1. 古いホームが今の入口へ飛ぶか
2. **代行請求が飛ばされていないこと**

の両方を毎週見ます。②を入れたのは、塞ぐ範囲が広がって実務を巻き込んだ時に、
その週のうちに気づくためです。

## 今回の学び

**push は反映ではありません。** 設定の書き方を間違えると Vercel はビルド前に失敗し、
**前のデプロイがそのまま配信され続けます**（＝画面は正常に見える）。
今回は `check-hosts` が「まだ 200 のまま」と赤で示したので気づけました。
**push したら必ず実物のURLを叩いて確かめること。**
